# 文件差异更新：开发首版

这套功能在 E5 与 MU300 仓库使用相同协议、生成器、网页插件和设备端引擎。
当前交付范围是**基础软件依赖一致的系统文件热补丁**。
首次迁移到带 OTA 插件的发行版，需要使用完整安装器更新一次；旧系统没有可信
的内置引擎时，电脑更新器会明确停止，不自动上传脚本并以 root 执行。

## 用户使用

1. 打开 `OpenWrt-Diff-Studio.exe`（Apple Silicon 原生构建对应 `.app`），选择
   旧版与新版完整发行 ZIP，也可通过 Python 命令行选择已解压目录。
2. 点击“分析差异”，检查机型、版本、文件增删与阻止原因。工具按文件内容和
   权限/所有者/扩展属性比较；不比较 ZIP 二进制，不修改输入包。
3. 导出 `.zip` 会生成可完整解压的电脑更新包，里面包含**一份** `update.ota`、
   原生更新器和 Python 入口。原生运行库复用生成器自身已校验的构建，不重复
   携带完整 rootfs、boot。选择 `.ota` 则只生成网页可导入的载荷。
4. 网页：系统 → 系统补丁，导入 `update.ota`，核对检查结果后应用。
5. 电脑：完整解压差异 ZIP，运行 `OpenWrt-Updater.exe` / `.app`，填写管理地址
   与 SSH 密码，先“连接并检查”，再确认应用。程序不依赖 SFTP，也不改变电脑
   路由。初次 SSH 连接的信任方式与现有安装器相同，本次检查到提交之间会核对
   设备公钥，避免把确认结果用于另一台设备。
6. 完成后重启设备，使所有服务加载新文件。网页可撤销最近一次补丁，恢复前会
   再次检查目标文件，用户随后手动修改过的文件不会被强行覆盖。

**只导入可信发布者提供的文件。SHA-256 用于完整性和版本匹配，不是发布者签名。**
本版没有公网自动下载、自动更新或发布者签名/密钥分发功能。

## 保留与冲突策略

- `/etc/config`、账号密钥、用户数据、流量记录、NV、固件、包管理数据库不会
  作为差异覆盖目标；用户额外安装的插件也不会被清理。
- LuCI 的 `www/` 页面、样式和脚本属于可更新系统文件；首次启动默认配置脚本
  不会借热补丁重新执行。核心启动运行库和更新器自身的变化要求完整安装器。
- OTA 自身的引擎和恢复入口不通过本版 OTA 自我替换。
- APK 基础软件集合、ABI/依赖变化要求完整安装器；自有看板的同依赖版本变更
  可以作为文件补丁，APK 数据库保留原包版本，实际生效版本另记 OTA 台账。
  之后用 APK 重装相应包可能覆盖热补丁，后续 OTA 会将这种情况报告为冲突。
- 设备版本、机型族、受影响文件的原始哈希、权限、所有者和扩展属性全部
  匹配才允许写入。不会提供“忽略冲突强刷”按钮。
- 普通目录删除会保留空目录，避免删除用户插件产生的内容；文件类型变化拒绝
  导出。软链接父路径、路径穿越、重复归档条目与包内脚本均会拒绝。
- 更改仅应用于本版清单，不承诺整机与新版完整镜像逐字节相同；被保留的用户
  配置不会因版本号改变而恢复出厂值。

## 事务与资源

- 写入前将原文件及不可变计划写到 `/etc/unisoc-ota/backup-<编号>/`，刷盘后才
  提交精简的事务进度。完整文件清单只写一次，避免随文件数产生平方级写放大。
- 每个文件使用同目录临时文件、校验、重命名；持久化进度先于相应文件修改。
- 网页与电脑共用已安装引擎。设备端工作进程脱离网页/SSH 会话，断开电脑不会
  主动终止写入；异常会尝试回退。重启时的早期服务仅在发现未完成事务时执行
  恢复，没有常驻守护、定时器或空闲轮询。
- 同时持有本功能事务锁和原有整包升级锁，已排队的 E5 整包升级会阻止 OTA。
- 保留最近一次手动回退副本；新事务成功刷盘之后才清理本工具的更早副本。
- E5 ext4 由桌面进程只读解析，不挂载、不依赖用户机器的 WSL；临时展开镜像
  放在输入包所在目录，一次只保留一个镜像，退出立即清理。MU300 tar 直接流式
  读取。WSL 仅用于开发测试创建小 ext4 样本，不是用户运行依赖。
- E5 已有 Python；MU300 新包会增加 Python 运行依赖以共用引擎。

## 尚未放行

**不比较新旧 boot 是否相同，也不以相同内核版本作为生成或应用条件。**
文件热补丁不包含 boot，设备端保留实际安装的内核版本记录，不冒充已经刷入新内核。
模块和核心运行库的变更仍受当前文件事务范围限制。当前不会刷 boot、
不修改 misc、槽位、分区表或系统容量。后续需要实现完整 boot 与模块配套的离线
事务，并验证实际 A/B 绑定及断电恢复，不能把简单覆盖 boot 宣称为可靠内核 OTA。
这种更新继续使用完整安装器。

没有实机 OTA 写入验证、实际断电验证或 macOS 原生运行验证；离线故障注入不能
替代这些验证。原生固件更新入口已屏蔽，但配置备份/还原仍保留。

## 开发与原生构建

```powershell
py -3.12 -m pip install -r installer/ota-requirements.txt
py -3.12 -m unittest discover -s installer/tests -p "test_ota*.py"
# Linux 中执行同一测试，可覆盖文件系统写入、进程退出和回退测试。

# 复用现有 installer/ui/node_modules 和 src-tauri/target，不复制第二份编译树。
cd installer/ui
npm run tauri -- build --no-bundle
cd ../..
py -3.12 installer/build.py --skip-ui
py -3.12 installer/build-ota.py --output out/tools/OpenWrt-Diff-Studio
```

Apple Silicon 同样使用 `installer/build.py` 和 `installer/build-ota.py` 的原生路径；
不能在 Windows 上伪造 Mac 构建。生成器自身会携带对应平台的更新器。

命令行：

```sh
python installer/ota-tool.py analyze OLD.zip NEW.zip
python installer/ota-tool.py generate OLD.zip NEW.zip update.ota
python installer/ota-tool.py update update.ota --host 192.168.9.1
```

公共根文件系统构建器和 E5 六机型组包器均调用 `installer/stage-ota.py`，不依赖
某一个机型的私有 stage，不会增加对 AT 命令、开机回放、充电或 USB 的操作。

## 2026-10-20 开发构建结果

- Windows 工具：`out/tools/OpenWrt-Diff-Studio-20261020/`，打开其中的
  `OpenWrt-Diff-Studio.exe`；必须保留同目录的 `tools/` 和其他附属文件。
  这份工具同时读取两个仓库的包，只有一份 Windows 原生构建。
- 使用实际 E5 发行 ZIP 解析了 6115 个文件、376 个基础软件包；实际 MU300 包
  解析了 2409 个文件、174 个基础软件包。只读输入，没有写入设备。
- 已测试封装后后端的分析与导出，以及原生 EXE 启动。测试生成的桌面差异 ZIP
  约 16.6 MB，其中实际 OTA 为 647 字节，其余是共用 GUI/Python 运行库。
  没有 boot/rootfs 副本。这里只是小型测试差异，不能据此推算实际更新大小。
- 浏览器回归覆盖分析/导出、应用完成与冲突拒绝，另外通过真实小 ext4 样本验证
  Windows 下的只读解析。Linux 测试覆盖写入中途进程退出、恢复和手动回退。
- 固件包尚未重新组装，实机尚未安装 OTA 插件或试刷补丁；Mac 仅接入原生构建
  路径，本轮未在 Mac 上构建或运行。

## 2026-10-21 Windows 启动与间距修正

- 已复现的闪退原因：Tauri 的 setup 阶段窗口 URL 仍可能是 `about:blank`，
  对它执行相对地址拼接会返回错误，引发 setup panic，Windows 退出码为
  `0xc0000409`。原先只等约三秒的启动检查不足以发现这个问题。
- 两仓库共用入口改为在创建窗口前指定 `WebviewUrl::App` 和标题，移除 setup
  导航。生成器、普通安装器和补丁更新器分别打开对应页面；Mac 导出的更新器
  以 `.app` 名称识别，避免被内部仍带 diff 字样的可执行文件名误判。
- 卡片下方与说明分隔线之间增加 24 px 留白；生成器与更新器共用，桌面及
  窄窗口的浏览器实际布局检查通过。
- Windows 重新编译并原地更新 `out/tools/OpenWrt-Diff-Studio-20261020/`。
  两项 Rust 路由测试通过；通过 Windows UI Automation 检查真实前端，生成器
  与实际导出 ZIP 中的更新器均连续运行 30 秒并正常关闭。更新器成功读取内置
  补丁版本；封装后后端的分析、真实 E5 ZIP 解析和桌面/网页合包导出也通过。
- 原生启动回归使用 `installer/tests/ota_frozen_smoke.py --native`，不修改
  发布程序的调试选项，不依赖开放调试端口。没有新增实机 OTA 或 Mac 验证。
