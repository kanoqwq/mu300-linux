# 流量策略 ucode 迁移：六轮回归

2026-11-20，E5、Pro 和 MU300 三个仓库均完成下列六轮离线测试。
三仓库合计 11,604 组原逻辑对照输入，以及 30,000 次双卡循环／210,000 次策略调用。

| 轮次 | 内容 | 三仓库结果 |
| --- | --- | --- |
| 1 | 直接执行原 Python 与新 ucode：配置、精确达线、卡槽、手动断网、执行状态；另跑 ucode 边界断言 | 通过 |
| 2 | 本地时区、UTC、夏令时，时钟回拨、跨日、错过任务与每日去重 | 通过 |
| 3 | 真实 libuci／libubus、实际 RPC shell、保存后即时检查、关闭后的空闲、流量采样回调、异常配置隔离 | 通过 |
| 4 | 实际网络重启入口的参数／SIM scope；并发保存与锁；强制中断恢复；持久化失败；ubus 消失再恢复；成功、延迟与失败结果 | 通过 |
| 5 | 原 Python 版本升级到 ucode、再次升级；分别回滚；保留无线配置、流量统计、套餐与策略配置；新增模块交付检查 | 通过 |
| 6 | 每仓库连续 10,000 次双卡状态循环、70,000 次调用，检查重复断网、漏恢复、重复重启、手动停网和切卡门控 | 通过 |

## 本轮发现和修正

实际重启入口测试发现原迁移引入了外部 `timeout` 命令依赖；精简 OpenWrt
环境未必提供该命令。已改用 ucode 的 `system(..., 210000)` 原生超时控制，
保持原来的 210 秒上限，输出文件只供串行工作进程使用，正常结束后删除。
修正后重新从第一轮完成全部六轮，最后核对生产源码未在测试途中改变。

对照测试让旧 Python 与新 ucode 都在 musl 环境执行；不能用主机 glibc
对不存在的夏令时墙上时间的不同归一化规则，误判设备端逻辑变化。
测试还按更新器既有“只提供最近一次回滚”的语义逐次验证，没有改变更新校验。

## 复现和证据

通过已有 `tools/build-release.py run` 调用
`openwrt/tests/traffic-policy-regression.py`，需要本机已有隔离 OpenWrt 测试镜像
和 `python:3-alpine` 对照镜像。Python 只运行于测试主机／测试容器，不随此策略进入固件。

迁移尚未提交时，对照默认读取各仓库 HEAD。提交后须用
`--baseline <仓库目录名> <已审查的迁移前提交>` 指定原实现；这只是测试证据来源，
不参与固件版本、ABI 或功能加载判断。旧实现不可用时测试会报错，不会跳过对照。

本机总结果位于 E5 工作区
`out/build-logs/20261120-073322-traffic-policy-six-rounds/results.json`，
包含每轮命令、日志、返回码、来源提交和测试期间的生产源码摘要。
设备和真实网络接口未参与这些测试，不能把它们称为实机验收；本轮未热部署或重新打包。
蓝牙、来电通知、IPv6 续租的 Python 迁移也未在本轮完成，后续同样要求至少六轮回归。
