# MU300 看板自动跟随上网卡

## 原因与行为

旧 `common.js` 的查看卡槽仅来自浏览器 `mu300-view-slot`，默认固定为 0。
网页内切卡成功会改这个值，实体快捷键由设备执行，不会修改浏览器存储；
因此实际已切卡，看板仍可能查看原卡。旧选择器没有自动选项。

现在默认“自动跟随上网卡”，也可明确手动查看 SIM1 或 SIM2。自动模式优先
使用设备现有 `/run/mu300-data-sim-actual`，再使用保存的上网卡作为尚无实际
记录时的初始选择。V50 显示所选物理卡源名称，但 RPC 仍只传逻辑槽位 0/1。

`mu300dash sim_get` 增加实际槽位字段，只读原有状态文件，不发 AT、不切卡。
看板沿用现有可见页面刷新周期；自动 RPC 和该周期的路由读取共用一个在途
请求，不添加独立轮询。手动查看不会被快捷键切卡改回自动；网页主动切上网卡
成功后延续原先同步查看的行为，并选为自动跟随。

旧存储键无法区分“默认 SIM1”和“网页切卡带来的值”，不将它当作新功能的
明确手动选择。新选项存入 `mu300-view-choice`，不会修改设备 UCI 配置。

首次打开页面须先解析实际卡再请求分卡数据。漫游、流量初始加载同步调整；
已有锁定、短信等写入如在确认期间遇到查看对象改变，会要求重新确认，避免
把旧卡表单的设置写到新卡。自动刷新读取仍会正常转向新的数据卡。
