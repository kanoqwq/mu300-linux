# UMS9620 CPU 电压偏移（F50／V50／U30 Air）

CPU 页面按固件的三个 domain 显示对应 CPU 核心、当前偏移、下次启动偏移和频率/电压表。
频率设置即时生效；电压设置独立持久化，仅在重启初始化调频驱动时应用。
范围 -50 至 +25 mV，步进 3.125 mV。默认全部为零，不添加超频档位、不关闭温控。
任何非零偏移都可能造成不稳定或数据损坏，范围限制不代表对每颗芯片都安全。

可手动输入偏移，也可点击每簇的默认（0）、-3.125 或 -6.25 mV 小幅预设。
预设只填写输入框，不直接保存，也不代表经过该芯片的稳定性认证。
保存前的二次确认逐簇列出当前偏移与下次启动偏移，非零配置默认聚焦取消。
取消（含取消按钮上按 Enter）不保存；只有确认保存才写入下次启动配置。

## 平台边界

插件只通过只读 cpufreq 属性发现 domain，不把 policy 编号或 E5 的电源轨映射照搬给 F50。
平台适配器 `/opt/mu300/bin/cpu-voltage-platform` 验证 SoC 以及两个 SML 分区；
没有匹配驱动或无法确认固件调压算法时禁用非零调压，仍可恢复默认。
已核验镜像优先走白名单；未命中时由只读原生 helper 检查 DHTB 完整性、
SMC 调用链、三域偏移及 CPU/SRAM selector 算法。不同版本只要接口匹配即可，
不要求两槽整镜像相同，不增加基带/网络等待，也不在运行中重复初始化。
U30 Air 的固件比对、精确哈希与 31 个电压表项目的启动验证见
[U30 Air 调压适配记录](U30AIR-CPU-VOLTAGE-20261019.zh-CN.md)。
插件不依赖 AT、基带、网络或其他看板进程，没有后台轮询调压任务。
现有内核内置驱动不能热替换；需要配套的新 Image 和模块。6.18/7.2 使用同一份驱动。

## 固件依据（只读分析）

UMS9620 F50，sml_a/sml_b 均为 1 MiB，SHA256：
`ff4782690fd805ff54fe34853ef8ee5c7e51c3259e20077c55373b50a4b259c2`。

SMC `0x8200060b` 经 `0xb000c784` 调用 `0xb0005ab8`：
bits 8..31 分别是三个 domain 的偏移字节，bit7 为负号，其余为 mV 幅度。
`0xb0005004` 保存每 domain 的偏移；`0xb0003354` 按
`ceil(mV * 1000 / 3125)` 调整 selector。`0xb00038b0` 分别对 CPU/SRAM
两张表调用该函数。PAIR_GET 路径 `0xb0004bae` 附近将 selector 乘 3125 返回 µV。
Linux 参数以 µV 表示，仅接受完整步进，编码用 `floor(abs(uV)/1000)` 反解上述舍入。
未写入 SML、NV、DTBO 或 PMIC 寄存器。不能将 `margin_set` 当作调压接口。

驱动模块参数只读；禁止 sysfs unbind，模块没有卸载入口，DVFS_INIT 有一次性保护。
OpenWrt 在 S08（根文件系统挂载之后）读取配置并加载模块；无插件使用零偏移。
其他系统由 extra-modules 加载；旧 rootfs 无平台适配器时，initramfs 从该 rootfs
加载零偏移模块以维持普通调频。绝不在早期初始化基带。

## 断电与启动验证

配置在 `/etc/unisoc-modem/cpu-voltage.json`。应用非零值前写入
`cpu-voltage-armed.json` 并同步磁盘。启动到 S99 后，逐个核对三个 CPU 簇的实际
电压偏移，匹配后记录为已确认。正常 shutdown 也可确认匹配的读回值；服务 stop
不修改记录。确认只说明完成了启动，不保证该偏移通过了长期稳定性测试。

已确认的同一组设置会在后续启动继续使用。F50、V50 等无电池机型直接拔电属于
正常使用，不会因为没有执行 shutdown 就撤销配置；即使后一次启动途中断电，
先前已经确认的设置也保留。新保存的不同偏移需要重新完成启动确认。

首次应用一组新设置后若未完成确认，下次先以默认电压启动，并暂停自动重试。
这只能证明首次启动没有完成确认，不能据此认定发生崩溃，更不能认定由调压引起。
配置不会删除或改名；进入默认电压的系统后重新保存即可明确重试。损坏的启动记录
同样暂停自动应用并提示原因。旧版本记录会在首次启动中迁移，不把旧标记视为
异常断电证据。旧版已生成的 `.json.rejected` 不会自动恢复，需要用户重新选择。
“恢复默认电压”保存全零，当前已生效的偏移仍需重启才撤销。
如果无法进入 OpenWrt，可在 Android 挂载 TF 后移除这两个 JSON 文件再启动。
此保护依赖文件系统可读写，不替代原有 Android 启动失败保护。它不监控运行中的
崩溃，不会因为单次 watchdog/panic 或缺少关机标记就撤销已经确认的设置。
