# NFC 关闭生效与 Wi-Fi 凭据同步（2026-11-19）

## 实机证据

当前连接的设备由 mu300-device 确认为 U30 Air。原有网页和 CLI 均与仓库源码一致。
用户在关闭后仍能重新读出 Wi-Fi 配网信息；现有 RPC 执行 off 后连续回读 enabled=0，
但手机仍能读出内容。保持 EEPROM 内容和关闭位不变，仅将 NFC CSN/GPIO190
明确拉高 300 ms 后，用户确认手机已不能重新读出内容。

原流程在 I2C 访问后退出 gpioset，只释放 GPIO 请求；实机 gpioinfo 仍显示该脚为输出。
原厂 fm11tag 的 /proc 访问分支已有结束写 1 的流程，gpiod 分支却缺少同一步骤。
本次参考的原厂 U30 Air 外版 fm11tag.ko 摘要为
`ce65bd76462d53dd14452f90d9cf2e5eac224fbddf7074a3a7ae19ecb16ddd4d`，
仅用于证据追溯，不作为运行时适配门槛。没有切回 Android、刷 boot 或操作基带。

## 修正

- U30 Air、V50 公用 CLI：释放低电平请求后明确拉高 CSN，并由 gpioset 自身保证
  保持 20 ms 后退出。兼容 libgpiod 1/2，继续使用各机型已经核对的 GPIO。
  正常结束、I2C 失败、INT/TERM 都走清理，拉高失败返回失败，不能报告应用成功。
- 内容写入与对手机开放分别处理。关闭时 Wi-Fi 改密事件仍可临时选中标签，写入
  最新 SSID/密码，结束后拉高，保留关闭位。无线同步遇到状态查询占用时最多等待
  5 秒，取得锁后才读配置，不丢弃一次普通的改密事件。无轮询常驻进程。
- 手动开启时，如果标签是 Wi-Fi 或空记录，先同步当前凭据，再开启；网址、文本
  原样保留。I2C 读取失败不会被管道掩盖，不会在读到半条记录后开启旧配网信息。
- U30 Pro/F50 Pro 保留各自原生 C 工具及控制脚本，不套用 Air 的 GPIO、总线和
  控制位。F50 Pro 的原生结束流程已有拉高；Pro 的开启操作已有最新凭据同步，
  无线配置事件在关闭状态继续清空配网记录，重新开启时恢复最新凭据。
  公共网页补齐 F50 Pro 到原生 owner 的映射，依旧由实际硬件支持检查决定是否显示。

这里验证的是手机不能重新读取配网内容，不声称芯片完全不响应射频或不能读 UID。
Pro 原生关闭策略仍是空 NDEF；没有据 Air 的一次试验修改 Pro 的射频寄存器。

## 交付与验证

修复进入两个仓库既有 rootfs overlay 和 LuCI 后端，由原有完整镜像、普通更新及
差分更新路径交付；没有新增配置文件、安装器依赖、服务或内核改动。历史 ZIP 不会
因源码修改自行更新，本轮未重新打包。

离线回归将 CSN 实际生效状态与 EEPROM 读回分开模拟，覆盖两代 gpiod、两款
MU300 NFC 引脚、开关、忙时同步、关着改密、漏事件后开启、保留自定义内容及
I2C/释放失败。Pro 另覆盖原生 F50 Pro 结束拉高、改密事件和重开后的新密码。
离线结果不能替代 V50、U30 Pro、F50 Pro 本轮实机碰一碰验收；本轮实机为 U30 Air。


最终回归：MU300 公共 CLI／网页 22 项、Pro 原生／网页 24 项全部通过。
两仓库公共 owner 与公共 NFC 用例已逐项核对一致。随后在连接的 U30 Air 原子替换
两份 NFC 脚本并核验摘要；实机 sync 后仍 enabled=0，独立 WSC 编码比对确认标签
内凭据与当前 UCI 热点名称、密码相符。wireless 配置摘要和 boot_id 未变。
本机备份及不含密码的回执保存在 MU300 work/nfc-csn-20261119/，不作为发布输入。
