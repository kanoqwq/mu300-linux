# U30 Air 关机充电灯交接

## 已确认的代码缺陷

`04_mu300_early_leds` 在 preinit 启动 `mu300-led boot on`，以
`.boot-chase` 令牌独占电池 RGB 灯。通常由蜂窝初始状态通知交还灯控。
`mu300-charge-mode` 在 S09 等待电源键或拔电，刻意不启动蜂窝；此前只调用
`battery`，没有撤销启动令牌，所以电池写灯被拒绝，旧 worker 继续轮播三色。

## 修复

仅在 U30 Air、charger 启动且未启用上电自启动时，在进入等待前调用
`boot off`，通过现有共享锁撤销令牌并显示已有电池状态。旧 worker 后续帧
因令牌失效退出。电源键启动或输入不可用而继续启动时，恢复 `boot on`；
拔电关机分支不恢复启动动画。正常启动、上电自启动、其他机型不进入这个分支。

沿用现有电池颜色、硬件呼吸、亮度开关、温控优先级和拔电关机逻辑。
没有修改充电电流、电压、基带启动流程或内核。

## 验证范围

安全命令替身执行关机充电门控，验证各退出路径及严格调用顺序；实际 shell
LED 控制器与门控联测低电红色、蓝色、白色呼吸及满电白色常亮状态，验证
等待期间启动令牌已经撤销、旧帧拒绝、按键退出后恢复正常启动令牌。
既有 worker 生命周期、硬件呼吸曲线、插拔延迟、超时灭灯和温控测试一并回归。

这些是离线测试；本次没有进行真实关机插电的目视验收。关机充电等待期间
的持续 SOC/满电事件刷新不属于本次轮播交接修复，不能用初始状态测试声称
完整充电周期灯色已在实机验证。
