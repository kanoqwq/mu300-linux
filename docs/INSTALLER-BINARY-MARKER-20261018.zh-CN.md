# 带零字节的分区准备标记检查

2026-10-18。E5 安装器实测发现：`head -c 128` 读取准备标记时，末尾包含 NUL 填充；
命令完成标记紧接其后输出，按行解析无法找到状态行，因而误报命令未完成。
E5 已在公共命令包装器中确保状态行单独起行，不修改磁盘上的准备标记。

MU300 当前实现不同：`Android.read()` 经 `download()` 调用共享 `pull_binary()`，
将原始数据暂存后通过 ADB pull 下载，校验长度、源/暂存/下载文件哈希。
命令输出只传递 ASCII 大小和哈希，原始零字节不经过按行完成标记解析。
续装检查先按 NUL 分隔再比较事务 token，因此本次检查没有发现同一个缺陷，未增加另一套传输兜底。

新增 `tests/test_desktop_binary_io.py` 用实际 BusyBox shell 和私有文件执行整个读取路径，
验证512字节、带 NUL 填充的准备标记完整往返，shell 元数据不夹带二进制，临时文件清理正常。
CLI 二进制传输3项与图形后端相关6项回归通过；这是离线回归，不代表 MU300 实机安装验证。
