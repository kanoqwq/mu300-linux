# U30 Pro NFC 与屏幕开关

本机硬件部分适用独立 `u30pro-bringup`。后续按用户要求，将共享网页入口
同步到 MU300 维护仓库供 U30 Air／V50 使用；E5 和原始参考仓库不变。

## 已确认的硬件和原有行为

本机 FM11NT08x 标签通过 `/dev/i2c-4`、地址 `0x57` 访问，原厂设备树
节点为 `ntag_fm11_gpio`。只读检查得到 CC `e1106d00`（872 字节数据区）、
SAK `00`，Wi-Fi WSC 记录的 SSID 和密钥与当前 AP 相符。检查未写 EEPROM，
未读取或修改 IMEI/NV。证据在 `work/u30pro-nfc/`，不作为发布输入。

原生 C 工具已随参考源导入，但此前没有接入运行时编译、发布或配置事件。
本次使用该工具的本机接口，不调用其他机型的 NFC 总线或复位 GPIO。

## 功能菜单

在屏幕既有“功能”列表中增加 `NFC` 开关，使用原生 toggle 插件，
沿用现有主题和交互。设置保存在 `u30pro_native_control.nfc.enabled`，
未配置时默认开启；明确关闭会保留到重启及配置保留更新之后。

开启写入当前选中热点的配网记录；关闭发布空 NDEF。这里控制的是
**NFC 配网信息**，不宣称关闭了芯片射频，也不提供门禁、支付或读卡功能。
标签数据区不属于基带 NV。关闭不会修改 Wi-Fi、基带或热点密码。

## 同步与写入

- 开机为一次性异步任务，不阻塞基带和热点启动；无线配置及 netdev 事件
  触发后续同步，不新增轮询服务或重试定时器。
- 使用公共 `hotspot fields` 的 AP 选择结果，支持多接口及重命名配置；
  不把 STA 当热点，不自行挑第一个接口。RPC 临时失败保留上次记录并报失败。
- 支持开放、WPA2 和 WPA2/WPA3 混合热点。纯 SAE、OWE 或企业认证不伪装
  成 WPA2；清除配网记录并提示当前热点不可用于 NFC 配网，不改变无线认证。
- 操作由 `flock` 串行化；进程退出自动释放锁。密码通过 stdin 输入，
  不放入 argv、日志、提示或运行状态文件。
- 相同内容不重复写 EEPROM。更新前先发布零长度 NDEF，写完正文后再
  提交长度并回读；中断时不向手机发布半条新凭据。只读或异常 CC 拒绝写入。
- 用户切换后显示完成／失败 toast，失败不报告成功。配置意图仍保存，
  以后有效事件会再次应用；状态开关表示用户保存的开关设置。

## 验证边界

离线测试使用真实 C 工具与文件模拟的 I2C 设备，覆盖独立 WSC 编码、
同内容免写、清空／恢复、写入中断、只读标签、畸形记录和密钥边界；
控制层覆盖持久化、热点事件不重开、接口与认证选择、RPC/硬件失败及机型隔离。
发布根还校验 ELF 摘要、原生菜单插件、脚本、服务启动链接和编码执行。

14 项 NFC 离线测试通过，真实屏幕程序的字体、菜单行及 toggle 加载也已验证。
目标根检查比对 59 项当前适配源码，并执行 ARM64 ELF 编码、脚本语法及服务链接检查。

经用户“允许热部署并验证 NFC 开关”授权，2026-11-03 已部署五项 NFC 文件，
不重启、不重启屏幕或基带。实机确认：关闭后为空 NDEF，reload 后保持关闭，
再开启后当前 SSID／密钥匹配且 UCI 保存为 1；CC 与 SAK 不变，热点和屏幕
输入／触摸／数据服务正常，boot_id 未变。结束保持开启。未写基带 NV／IMEI。
文件和标签原件备份及结果在 `work/u30pro-nfc/deploy-20261103-181146/`；
备份不收入发布，标签备份含配网信息，不用于公开日志。此前 SFTP 未配置导致
首次尝试在任何部署写入之前停止；正式部署通过 SSH 二进制 stdin 传输并核对 SHA256。

**尚未做手机实际碰一碰入网测试**，上述实机读写及菜单程序离线验证不能替代这一项。

## 同日网页入口及名称调整

屏幕和完成提示统一名称 `NFC`。网页“设备管理”新增 NFC 卡片，沿用看板
主题与现有单一开关样式，支持中文／英文／土耳其文，显示读取／应用中的
加载状态和语义化错误；只读会话禁用写入，不支持 NFC 的机型隐藏卡片。

`unisoc-nfc` 的 get/set RPC 只做机型到已选定 owner 的映射：U30 Pro 调用
本机 `u30pro-nfc-control`，U30 Air／V50 调用现有 `mu300-nfc`。不在 owner
缺失或失败时换用另一套后端，不依赖 SIM 或基带就绪，不重启无线或基带。
U30 Pro 屏幕／网页使用相同持久化配置；其他两款保留原有芯片 RF 配置位。

原 `mu300-nfc` 增加无敏感内容的 state 查询和 GPIO／EEPROM 访问互斥；
其 Wi-Fi 同步保留 RF 关闭状态及自定义 URL／文本。两个仓库均接入 Makefile
及 rootfs 构建权限，U30 Pro 的准备根回归覆盖新页面、RPC、ACL 和脚本。

本轮离线结果：20 项原生 NFC／网页 RPC 测试、10 项现有 NFC 工具回归通过；
两仓库各 18 组 NFC 语言／主题／视口浏览器用例，以及 6 组原 USB 页面用例通过。

经“先给我 u30pro 热修补好”授权，已部署七项文件并重新加载 RPC 服务；
通过真实 HTTP JSON-RPC 验证读接口、写权限及保持原值的 set 操作，静态网页
资源摘要一致，NFC 保持开启，屏幕输入／触摸／feed 正常，机器未重启。
记录和原件在 `work/u30pro-nfc/web-deploy-20261103-184623/`。该次热部署未重打固件包；
随后用户要求重打完整包，已通过 sources/finish 收录网页入口，并通过 64 项
准备根源码比对及目标 RPC、权限和原生 NFC 检查。U30 Air／V50 的这次网页接入
仍是离线验证，未称作实机验收。
