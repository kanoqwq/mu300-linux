# SIPA 发送回收与接收 DMA 修正

日期：2026-11-25。范围是与 Pro 五项 SIPA 检查对应的 MU300 实现；
没有把 Pro 的整套驱动移植到 MU300。

## 核对与改动

| 检查项 | MU300 原状 | 本次处理 |
| --- | --- | --- |
| 发送失败后的 skb 所有权 | 已释放 skb 的分支已返回 OK；永久错误仍返回 BUSY | 保留前者；永久错误计错、释放一次并返回 OK，只有流控错误继续 BUSY |
| 重试包头 | 已按是否实际 push 回退包头、还原校验和 | 补充 skb_cow_head，在获取校验和字段指针前保证包头空间与可写性 |
| 普通 NCM 触发旁路 | 没有 Pro 的那段误触发逻辑 | 无需引入新的旁路判断 |
| TX 完成队列 | NULL 项推进数量错误，匹配重试未重新同步 DMA；解锁后继续访问可复用 pair | 按实际处理的前缀推进；未匹配项最多重新同步三次；锁内摘除、解除映射并取走 skb，解锁后释放 |
| RX DMA | 持久页 FROM_DEVICE 映射却以 TO_DEVICE 同步；初始化与重建缺少所有权交接 | 页映射及交接统一 BIDIRECTIONAL；堆 skb 保持单次 FROM_DEVICE 映射 |

持久页同时存放设备写入的数据和 CPU 写入的 skb_shared_info，因此双向映射
不是把所有接收内存都改为双向。首次填充、整页补充和剩余节点补充共用
sipa_build_rx_skb；CPU 构造前取得所有权，软件所有权环接纳后才同步给设备、
发布描述符。初始化跳过分配失败的槽位时，DMA 地址仍对应实际缓冲。
接收完成先取得 CPU 所有权，再校验或释放，避免异常路径重复解除映射。

TX 未匹配描述符不会释放其他 skb 或虚增发送额度，后续有效项仍可回收。
如果硬件永久丢失完成记录，本修正不凭空重建它。保留 MU300 的接收参数、
校验和行为、诊断、流控通知及原有线程生命周期，不加入周期轮询或硬件重置。
