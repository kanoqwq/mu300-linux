# ZTE M3 (MU5352)

M3 uses the existing `u30air` hardware path. This support recognizes the tested
Android identity `ro.product.model=MU5352`, `ro.product.device=MU5352` and
`ro.board.platform=ums9620`; other M3 names/boards/platforms are not inferred.
The shared OpenWrt Tools installer carries the matching classifier in its own
repository. Native U30 Pro/F50 Pro packages remain different products.

Installation derives `/etc/mu300/device-model=m3` from that device's Android
properties, after restoring settings. Generic images do not embed this marker.
`mu300-device` still returns `u30air`; `mu300-device --model` returns `m3` only
when the board detector agrees with that hardware profile. A marker cannot
turn an F50/V50 into a U30 Air. Reinstallation on another Android removes a
stale M3 marker. In-place updates retain it with the existing `/etc/mu300`
configuration preservation.

OpenWrt's generated model label is `ZTE M3 (MU5352)`. M3 has no NFC tag, so
all NFC actions, including startup sync, stop before GPIO/I2C access. U30 Air
and V50 NFC behavior is preserved. This adds no kernel or radio changes.

The earlier M3 B18 test associated with dikeckaan/mu300-linux#456 established
the shared U30 Air path: rooted TCP ADB installation, OpenWrt boot, cellular
registration, WPA2 hotspot, SSH/LuCI and an Android/Linux roundtrip. The owner
also confirmed SIM2 band/cell locking. Those results are not a hardware test
of this maintained branch or its current installer build. This adaptation has
fake-root/property regression coverage only; no new flash/resize/NV operation
was performed. NFC absence is a product distinction, not an NFC hardware test.
