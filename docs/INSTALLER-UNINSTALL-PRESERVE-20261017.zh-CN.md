# 卸载：保留未加密 Android data 与明确格式化选择

日期：2026-10-17。此页为开发验证报告。用户步骤见 `installer/GUIDE.md` 和帮助页“卸载并归还空间”。

**后续修订：原安装记录已不再是硬性条件。无旧记录时的设备端证据、相邻分区边界及新增验证见 [无原安装记录卸载](INSTALLER-UNINSTALL-EVIDENCE-20261017.zh-CN.md)。本文下述“原记录缺失仍停止”只描述本修订前的限制；保数据及明确格式化选择规则继续适用。**

## 处理规则

- 可靠确认当前 Android 未加密、`/data` 直接位于 userdata、文件系统身份和容量可读、所带检查/扩容工具兼容时：删除独立 OpenWrt 分区，离线检查并扩大 userdata，保留 Android 文件系统和数据。
- 加密状态、设备映射、文件系统或工具兼容性无法满足保留条件时：返回具体原因，询问“无法保留 Android 数据卸载，是否格式化？”。取消不写设备，也不创建卸载记录。
- 选择格式化后重新探测设备，仅生成明确标注清空 Android 应用、账号、照片及内部存储的新计划。仍需最终确认才执行原厂 Recovery 重置。
- 原先来自未分配空间的安装：只释放该空间，不扩大、检查修复或格式化 Android data。
- 原记录缺失、GPT/硬件身份不符、其他分区变化等证据错误仍停止，不能通过“同意格式化”绕过。

格式化选择使用一次性 token，绑定当次探测的 CID、Android 槽、分区快照、加密状态和文件系统证据。换设备、观察结果变化、无效/过期 token 都需要重新询问；客户端提交一个布尔开关不能授权重置。

## 后端与恢复

E5 为规范源，共用 `backend/uninstall*.py`、React 界面和协议。新卸载记录内部版本为 2；旧版未确认计划要求重新生成，已下发的版本 1 记录沿用原合同，不更改已确认的设备请求。

保留流程重新验证 UUID、文件系统种类、设备节点、容量、加密状态及维护工具 SHA256。工具和请求随一次性 ramdisk，不能依赖 userdata 清空后的文件。工具沿用各仓库已校验的 ARM64 载荷，没有依赖电脑上的 Linux 工具执行设备操作。

离线环境先确认无挂载/holder，并检查工具及原文件系统，检查失败时不提交 GPT。随后提交经过证明的 GPT 恢复快照，要求内核重新读取分区表并核对 userdata 节点的起点与完整大小，并核对后续读写节点的设备号，再对该节点执行检查、扩容和再次检查。只有 UUID、实际文件系统容量及镜像回读通过后才恢复 Android 启动。保留路径不带 Recovery wipe 请求，失败也不会转去 mkfs/格式化。

电脑最终再次核验实际容量及同一文件系统身份。若 GPT 已恢复、Android 可返回但扩容未完成，保存待扩容状态；明确重试只在身份、布局和同一待完成 worker 镜像可回读确认时重新设置 misc，继续检查/扩容，不重新分区。证据不足时停止。执行阶段错误不能静默转换为重置；仍需恢复检查和新的明确操作。

F2FS 扩容使用普通 `resize.f2fs -t`，不复用缩容的 `-s` 参数。这个区别也有[上游工具手册](https://kernel.googlesource.com/pub/scm/linux/kernel/git/jaegeuk/f2fs-tools/+/refs/heads/master/man/resize.f2fs.8)支持。当前随包工具是 1.16.0。另通过 QEMU 检查实际 ramdisk BusyBox 的帮助及参数支持：它提供 `blockdev --rereadpt`，不支持 `losetup --sizelimit`，所以保留流程只接受核验后的真实 userdata 节点，不使用无长度限制的 loop 回退。测试机上的旧 1.14.0 曾返回 0 却保留旧容量，最终容量检查正确拒绝；保留计划也拒绝未经确认的旧版 F2FS 工具，不能只以进程退出码判定成功。

## 验证范围

- 两仓库完整 Python 回归各 177 项：E5 跳过 9 项，MU300 跳过 11 项，其余通过。新增 `test_uninstall_growth.py` 12 项，其中 2 项真实文件系统测试在 Windows 跳过，另在 WSL/QEMU 执行通过。WSL 的 3 项 BusyBox 事务测试亦通过。
- TypeScript `tsc --noEmit --incremental false` 及 `uninstall_smoke.py --source` 通过；Vite 只使用临时缓存，没有生成 dist。

- Python 回归覆盖：未加密 ext4/F2FS 自动保留、不发格式化请求；加密/未知状态/dm 映射/缺工具停止并询问；布尔开关不能授权重置；token 过期、观察变化和有效选择；执行前再次检测加密变化；导入计划一致性；最终容量不足及仅 misc 的扩容续作；未确认旧计划不能直接启动。
- BusyBox 临时稀疏文件执行实际 GPT/BCB/boot 读写，增加 Android A/B 保留分支和 fsck 失败时不写 GPT、不写重置请求的检查，以及分区表重读失败/设备节点号不符时不扩容、不重启的检查。该层仅模拟工具调用；文件系统操作另行真实执行。
- ext4 和 F2FS 使用带用户文件的临时镜像，实际执行生产检查/扩容函数，并再次执行完成后的检查。ext4 512→768 MiB；F2FS 768→512 MiB 模拟原缩容，再恢复至 768 MiB。UUID、实际容量不变式通过；大于 inline 容量的用户文件分别经 debugfs 与 dump.f2fs 按 inode 读取，逐字节相等。
- 上述文件系统测试同时检查了随包 ARM64 工具：从现有 E5 发布载荷及 MU300 维护包只读提取到系统临时目录，通过临时解包的 QEMU user emulator 执行。没有安装全局依赖、接触设备或重新生成发布载荷。
- E5/M8/T551M 及 MU300 现有 boot 的检查点及 ext4/F2FS 工具追加大小在内存中验证，不写回镜像。
- 浏览器源代码检查覆盖：报错与格式化询问、取消后无执行请求、选择格式化后的计划、最终确认、未加密保留/原空闲区/重置三种提示、中英文及最小窗口。后端桥接使用测试传输。
