# 电池与电量页面（2026-11-03）

沿用已验证的 U30 Pro 页面与统计规则，原 U30 Pro 仓库及其屏幕接口不变。本仓库使用独立的 `unisoc-battery-history` 服务/RPC；E5 本次只做网页，不修改实体屏幕。

蜂窝 → 电池与电量包含电量、状态及净电池功率/电流/电压、电池使用时间、预估续航四卡；历史曲线支持自上次充满、自上次充电、24 小时、7 天。充电管理从设备管理移至该页底部，原硬件控制接口及用户设置不变。中/英/土耳其语，Aurora 与默认主题、手机与桌面均有页面回归。

**无电池不开服务**：init 在创建 procd 实例前调用只读探测，Battery 类型且 present 不为 0 才启用。不创建采集实例、定时器、历史目录或菜单；仅有一次开机探测。MU300 还沿用现有 mu300-device 规则排除 F50/V50 的虚拟 FGU。并非仅在网页隐藏卡片。

E5 优先读取 aggregate battery；MU300 U30 Air 由显式 family profile 指定 bq256xx-charger 的状态，不能套用 E5 CM 或 U30 Pro 的硬件节点。不访问 AT、不改 FGU 校准、射频或充电参数。

保留现有 10 秒采样、每分钟一条、十天保留方案。历史目录为 `/etc/mu300/battery`，常规更新的配置保留路径已覆盖此目录。充电/记录不足/电量不降/关机间隔不作续航推算；空档不连曲线。功率为电池净值，不是充电器输入值。对无电池、present=0、FGU 名称变化、各 E5 profile、充电状态归属、保留/重载、曲线空档和 LuCI 实际流式 JSON 解析均有测试。

菜单 JSON 使用 ASCII 转义，防止当前 LuCI ucode 流式读取带未转义多字节标题时丢失整个菜单。菜单缓存仅在实际电池存在状态改变时失效。

发布集成：`openwrt/build-rootfs.sh` 及 `tools/build-openwrt-tf-magisk.sh` 的 7.2/6.18 共用路径；两个 Makefile 均登记可执行权限和 postinst 启动；Po/LMO 同步，启动/停止链接和必需资源已加入正式发布校验。没有电池历史/实机数据写入发行源目录。

本轮为源码及离线验证；未在本仓库机型热部署，也未重新生成发行 ZIP。U30 Pro 的实机结果不是本仓库机型的硬件验收。
