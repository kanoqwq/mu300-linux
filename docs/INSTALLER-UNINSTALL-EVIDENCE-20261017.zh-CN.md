# 无原安装记录卸载：设备证据与空间边界

日期：2026-10-17。开发验证报告。用户操作说明见 [安装器使用指南](../installer/GUIDE.md)。本修订取消“必须保留原分区创建事务”的硬性限制，沿用保数据检查、明确格式化选择及离线执行流程。

## 行为

- 有匹配原安装记录、完整身份信息和已校验 GPT 备份时优先使用，仍检查其他分区没有变化；原空闲区安装只释放为空闲，原缩容按已证明的边界归还。
- 无原记录或原备份已不可用时，检查当前双份 GPT、Linux 文件系统分区类型、GUID、对齐、内核节点起止及容量、挂载/映射占用、另一槽的 Linux boot/ramdisk 路由，以及已安装文件系统内的固定标记。不是只检测 `e5root`/`mu300root` 分区名。
- 可信 OpenWrt 分区紧邻 userdata 尾部时，仅合并这一个分区的范围，userdata 新尾部等于当前 OpenWrt 分区尾部。不猜历史容量，也不合并额外隐藏空间或其他未分配范围。
- 不相邻时只移除 OpenWrt 分区并释放为空闲，不跨越间隔或其他分区扩大 Android。计划分别显示 Android 前后容量、归还 Android 的容量及释放为空闲的容量。
- 保留 Android 数据的要求不变：明确未加密、直接 userdata、身份及容量可读、工具支持。否则先说明原因并询问是否格式化，仍需最终确认；格式化选择不能绕过分区归属和边界检查。
- 本次卸载始终新建持久记录、当前布局快照、boot/misc 及启动链备份。没有旧安装事务与没有本次卸载恢复记录是不同情况。新记录丢失且设备已存在待执行卸载标记时，仍须恢复记录，不能重建另一项破坏性操作。

## 实现与限制

共用规范源为 `installer/backend/uninstall.py` 和新增 `install_evidence.py`，同步到 MU300。无原记录的计划使用内部卸载 schema 3；保留 schema 1 已下发操作及 schema 2 原记录计划的恢复能力。

固定文件通过电脑上的纯 Python ext4 只读解析器读取。目录、inode、块及 extent 均校验长度和界限；有元数据读取预算，拒绝符号链接、稀疏或异常 extent、未正常卸载及不支持的文件系统。不会挂载/修复根分区、执行其中的脚本，也不新增用户环境依赖。二进制元数据传输继续使用已校验的设备临时文件和 ADB pull，没有 Base64 分支。

E5 使用对应 boot 路由、当前磁盘的 `etc/e5/part-root` 和 OpenWrt 身份；MU300 使用 native `part`/已完成的 `install-part` ramdisk 路由、容器启动标记、`openwrt/etc/mu300/desktop-mode=part` 和 OpenWrt 身份。TF、userdata 镜像、未列入 GPT 的旧隐藏区域及未知自定义布局不冒充独立分区安装。

执行前重新核验证据。导入/重启后从已保存的当前快照重新计算允许变更，重新算哈希也不能扩大范围或修改 NV 等无关条目。设备证据加入格式化选择指纹。启动准备中断时，原 Linux 证明可从本次卸载的已校验 boot 备份读取；实际 GPT、misc、Android 槽及当前根分区证据仍须复核。已经下发的任务不再依赖即将删除的根分区标记，不重放缩放、格式化或完成的写入。

- 两仓库完整 Python 测试各 195 项：E5 跳过 11 项，MU300 跳过 13 项，其余通过。
- 新增设备证据测试 18 项，覆盖空电脑记录、损坏旧备份、原记录优先/冲突拒绝、E5 与 MU300 Android A/B、相邻归还/非相邻释放、额外尾部空间保留、同名伪标记、占用/错误节点/脏文件系统/错误 boot 拒绝、格式化不能绕过证据、导入越界/无关分区/节点篡改拒绝、重新打开续作、启动准备的真实请求生成和备份顺序。
- WSL 执行卸载相关 52 项，51 项通过，1 项因本机旧 F2FS 工具跳过。包含实际 BusyBox 在临时普通稀疏文件上的 GPT/BCB/boot 读写、保数据 ext4 扩容及最终容量检查。
- 新只读解析器另用 `mke2fs` 创建的真实 ext4 普通文件验证 1 KiB/4 KiB 块、64 位描述符、metadata checksum、索引/多块目录、标记和符号链接拒绝；前后整文件 SHA256 相同。挂载/映射占用检测也用真实 POSIX shell 和临时 sys/proc 文件验证，错误或不可读元数据不会判空闲。
- 只读检查现有 E5/M8/T551M boot 资产；MU300 7.2 现有载荷在内存中生成 Android A/B 的 `part` 及 `install-part` 路由，证据识别通过，不写回发布包。
- TypeScript 无输出类型检查通过。源代码 Vite/Playwright 六组卸载场景通过，覆盖中文/英文、浅色/深色、有/无原记录、保留/释放/重置、取消和一次最终确认、最小 800×650 窗口及 Android 完成页。截图新增 `uninstall-plan-device-zh.png`、`uninstall-plan-device-gap-en.png`。
