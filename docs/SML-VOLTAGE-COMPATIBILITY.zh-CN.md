# SML 调压兼容性：白名单优先、算法匹配补充

2026-11-01，E5 公共 CPU 后端和 MU300 平台适配器采用同一规则。

1. 核对已适配 SoC、配套 CPUFreq 模块的启动偏移参数，页面另外检查实际电压域接口。
2. 每份 SML 先匹配原有白名单。命中即可，不运行额外分析程序。
3. 未命中时运行静态编译的只读 `sml-voltage-check`。不需要 Python 反汇编库、
   网上查询、型号特例或新增固件哈希。
4. 两槽可以是不同版本；各自匹配相同调压 ABI 即可，不比较整份镜像是否相同。

算法识别检查 DHTB 的动态长度与 payload 校验和，并从实际 AArch64 指令中定位：

- SMC `0x8200060b` 的跳转表入口与传参关系；
- 原厂两类初始化/解码实现：循环解码，以及初始化后调用展开解码器；
- 三个偏移字节位于 bits 8～31，每字节 bit7 为符号，低七位为 mV；
- selector 使用 `ceil(mV × 1000 / 3125)`，按符号修改 16 位电压表；
- 指向同一域状态的实际表调用：旧实现有两组 CPU/SRAM 配对和第三域表路径，
  新实现三组配对。跟随指令中的相对分支和数据地址，不固定文件偏移。

这是一套针对已审计厂商实现的 ABI 识别器，并非通用反汇编器或形式化证明。
签名区、版本、无关代码或代码整体按页迁移可以不同；如果编译器生成了尚未识别的
另一种实现，不能仅凭找不到特征就断言原厂不支持。此时保留原厂电压，并明确报告
“尚未匹配到本机 SML 的调压协议”，需要扩展实现识别，不能直接忽略校验。
动态 SHA256 仅核对 DHTB 自带的完整性信息，不是另一份固件版本白名单，也不验证厂商证书。

源文件为 `tools/sml-voltage/sml-voltage-check.c`；E5 对应
`devices/common/sml-voltage-check.c`，本机回归检查两份内容一致。
E5 公共 UI stager 和 MU300 rootfs 构建都会携带 helper；仅重打用户态即可，
不需要为本次识别逻辑重编未改变的内核。使用既有静态 ARM64 编译器，固定小型产物缓存
在 `out/sml-voltage/`，不创建新的 SDK、内核树或 rootfs 副本。

早期分区缺失、读取失败或 helper 尚未安装不缓存为永久拒绝。白名单/算法成功结果
按本次启动缓存；新的后端忽略旧版缓存。保持默认零偏移、合法配置持久化、关机充电
使用原厂电压、异常启动回退，以及每次启动只初始化一次；不在运行中重载或重做 DVFS_INIT。

离线测试使用原厂文件检查多版实现，并构造签名变化、整页代码迁移、有效校验和下的
错误 SMC/解码/量化及断开的 CPU/SRAM 调用、截断和边界错误。宿主 C 以 UBSan 执行，
另检查静态 ARM64 交付件。所有测试均不执行固件代码、SMC 或硬件写入，不能替代
Y60 的实际电压与长期稳定性测试。
