# 差异包生成器与统一更新入口

## 已确认的产品范围

- 独立 Tauri 工具，复用现有安装器的界面组件和设计。
- 输入旧版包、新版包，分析后展示差异、兼容范围与体积，再导出差异包。
- 同一份差异包支持 OpenWrt 网页导入，以及解压后通过内置电脑更新器更新。
- OTA 插件完成后默认内置到 E5、T551M、M8、T512N、远航 41S、K1，以及
  MU300/F50/V50/U30 Air 对应发行包，用户无需另装。
- 两仓库使用一致的差异包协议，各自保留机型和内核兼容校验。
- 对系统文件生成差异，不直接比较压缩包字节；只更新差异覆盖范围，保留
  用户额外插件、配置、流量记录及其他数据。冲突必须明确显示。
- 内核变更时携带完整 boot 与配套模块；不重复放置多份 boot/rootfs。
- 旧版匹配、文件哈希、空间检查、持久化事务与失败恢复在实际实现时一起完成。

## 本轮已经落地：屏蔽 OpenWrt 原生刷固件

两仓库保留系统配置备份、还原及重启，移除 LuCI 原生固件刷写区和对应 ACL。
原“Backup / Flash Firmware”菜单改为“Backup”；不移除整个配置备份页面。
自动升级组件原有的移除规则保留，不影响用户通过 APK 安装或管理普通插件。

公共 ucode 策略应用到根文件系统构建、E5 六机型公共组包、LuCI 包安装和首次
启动路径。策略是一次性应用，不增加后台轮询，不改基带/AT/回放/USB 启动顺序。
匹配基于当前 OpenWrt 25.12 已安装的 LuCI 视图结构，未知新结构明确失败，
不盲目删除备份控件。标准 LuCI 的 Backup 文本继续使用原有翻译。

两仓库 sysupgrade 防护只允许明确的配置备份、还原和列表操作；拒绝固件参数及
混合操作。特别补上原先不能经 LuCI 执行的配置还原，不把原生刷写能力重新打开。

## 验证范围与尚未完成

- 防护脚本的合法备份/还原和固件拒绝、菜单/权限保留、重复应用及未知视图不写入
  已通过离线测试；使用已有 OpenWrt 容器运行实际 ucode，未构建新镜像。
- 已实现首版 Tauri 分析/导出与电脑应用界面、E5 ext4 / MU300 tar 读取、统一
  文件差异协议、设备事务引擎、网页导入/回退，以及公共构建默认内置。
- 当前只允许相同内核和基础依赖的文件热补丁；boot/内核/模块变化仍阻止导出，
  后续需单独完成动态槽位绑定及离线内核事务。详细限制见
  [使用与实现说明](OTA-DIFF-USAGE.zh-CN.md)。
- 离线测试覆盖校验、冲突、保留用户数据、回退、模拟进程中断恢复和真实小 ext4
  解析；没有实机 OTA 写入或真实断电验证，不能把它们称为实机通过。
