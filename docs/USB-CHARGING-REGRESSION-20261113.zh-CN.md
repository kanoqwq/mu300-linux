# MU300 系列 USB／充电离线回归（2026-11-13）

范围：`minikano-openwrt-feats` 的自动／强制 USB 数据角色功能；覆盖共享
6.18.54、7.2.8 路径及 U30 Air、F50、V50 的运行时隔离。用户本轮明确选择
“暂时不方便，先做离线回归”，没有进行实机写入、角色操作、刷 boot 或重启。
上轮 U30 Air #109 的带坞实测只作参考，不能计为这次充电修正的硬件验收。

## 发现并修复的边界

非 PD 充电器已完成 BC1.2 识别后，在同一次 VBUS 连接中强制数据主机，
PHY 原先会发布 UNKNOWN_TYPE。BQ 消费者随之按未知输入的 500 mA 预算工作；
原先 DCP 的 2 A 或 CDP 的 1.5 A 额度因此被降掉。PD 合同分支有独立优先级，
不受这条额度回落路径影响。该结论来自编译实际生产函数的可重现失败，
不是根据本轮实机充电功率推断。

修正只保留同一连接中已经完成的检测结果，不在主机数据线上重新运行检测。
实际 VBUS 事件仍在事件锁内立即清空类型并递增 generation；过期结果无法发布。
新接线、未识别输入继续保守预算；不扩大电源声明，不更改 PD、升压、用户停充、
电池 CV、终止电流或定时器，不增加后台轮询。该 BC1.2 路径仅启用于有电池板型。

新增 SDP／CDP／DCP 数据角色切换及实际拔插清空用例。修正前同一用例失败，
修正后 PHY 生产函数和实际 BQ 消费者均通过。

## 回归项目

| 范围 | 检查内容 |
| --- | --- |
| 数据角色 | 自动／强制主机／强制设备、最新请求优先、并发 Type-C 事件、失败不覆盖原策略、关机退出 |
| F50／V50 | 不开放自动覆盖、不启用电池/PD 硬件访问、原角色操作、提前主机与 UDC 事件交接 |
| 数据链路 | USB 网卡接入 LAN、已有桥/WAN/VLAN 归属、NCM/RNDIS 重绑、NCM 队列耗尽与定时器 |
| PHY | 正反插 TCA 同步、host+sink 的内部 valid、首次初始化、PD RX/reset/恢复、失败回滚 |
| BC1.2 | SDP/CDP/DCP、同连接预算保留、真正拔插清空、延迟/过期事件、失败/超时、禁止主机 DPDM 检测 |
| 充电仲裁 | PD 优先、Rp 明确 1.5/3 A 额度、未知输入限制、用户停充、OTG 升压与受电独立 |
| 电池和开机 | 原厂 CV 量化、电池/芯片电流边界、满电条件、充电启动、限电回差、无电池机型排除 |

## 测试环境修正

首轮充电控制测试误用了 AMD64 ucode 镜像作为 ARM64 容器；现改用已存在的
`mu300-charge-test:20261016`，不拉取新镜像。原生看板测试容器补传其三个
显式夹具环境变量，避免测试读取容器自身的空电池目录。以上是本次测试命令
的修正，不是设备产品代码变更。

6.18 的既有准备目录缺少仓库已存在的 0028 电池信息生命周期补丁。使用
受版本控制的 `upstream/build.sh`／`build-modules.sh` 更新同一源码与对象缓存，
没有换旧包、跳过失败、修改测试期望或新建源码树。两条内核的配套验证产物
位于现有 volume 中 `/src/usb3-validation-6.18.54`、`/src/usb3-validation-7.2.8`。
本次没有组装正式发布 ZIP。

## 结果和边界

最终任务 `20261113-055424-usb-charge-regression-final-13313` 状态 complete。

- 综合测试实际运行 86 项，85 项通过、1 项跳过；跳过项缺少未分发的原厂
  U30 Air modem-loader 样本，属于充电启动中的原厂加载器对照，不把它记为通过。
- 两条内核分别执行 BC1.2 生产者／BQ 消费者、128 组 Rp／状态组合、原厂 CV
  编码与配置边界、4096 组保留电量编码、NCM/RNDIS 描述符解绑和 NCM 定时器
  回归；另执行角色并发、PHY/TCA、PD RX/reset/恢复等，共 19 次脚本回放通过。
- 6.18.54 完成 Image／195 个配套模块，7.2.8 完成 Image／202 个配套模块，
  均完成 BTF 检查。生产头文件
  与实际准备树逐字节一致，Image／配置／全量模块 SHA256 清单校验通过。
- 本轮没有改动自动／强制角色覆盖实现，也没有修改 Type-C/PD 电源策略。
  唯一产品代码修正是上述同一 VBUS 连接的 BC1.2 完成结果保留。
- 本轮新修正没有部署到设备。上轮已部署的 U30 Air #109 不包含此项修正。

用户随后补充：同一多级坞使用带 PD 协议的电源时工作较好，普通 5V 电源下
可能只充电、不识别或只有 480，拔插后可恢复 5G。这是尚未完成现场对照的
供电／协商条件差异，不能据此认定“强制主机切回自动”是其唯一原因，也不能
宣称本次 BC1.2 额度修正已经解决了该坞的枚举问题。

已知扩展坞带电重启的间歇 480 Mbps、
特定坞的硬件兼容现象不在本轮修复范围。离线检查不能替代真实 A-C／C-C 充电器、
电池供电 OTG、PD 外供坞及实机热拔插的电气验证。
