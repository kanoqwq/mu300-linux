# 在线 F2FS 保数据缩容与续装修复（2026-10-29）

## 本次安装报错的确认原因

畅行60的原 Android 在 B、OpenWrt 目标在 A。电脑已经完成空闲区 GPT
分区创建，但旧 GUI 的 free-space 续装记录漏存 android_slot/linux_slot。
续装代码把缺失角色按历史 A/B 处理，误报槽位改变，尚未写入 OpenWrt 根。
这不是在线缩容失败，也没有理由重新缩容或清空 Android。

新记录显式保存动态角色；旧记录仅从绑定的原电脑事务恢复角色，核对
串号、CID、userdata 几何、GPT effect 和记录路径，不从当前槽位猜原角色。
真正槽位改变仍停止。已修复本机该条续装记录，原件另存；没有因此写设备。

## 新的图形安装器流程（两仓库）

1. 已有足够未分配空间时直接使用，既不缩容也不清空。
2. 否则默认优先 Android 在线 F2FS 保数据方案；原离线清空方案保留为可选项。
3. 只读确认实际挂载源、双超级块、UUID、完整 userdata 映射和空间。
   支持公共 eMMC/UFS 拓扑及 512/4096 GPT；块级 FDE、多层映射、未知偏移
   不伪装成已支持。FBE/metadata 加密使用 Android 已建立的解密映射。
4. 先备份原 GPT/启动链，metadata 加密时另存有大小限制的 metadata 备份到电脑。
   不备份整个 userdata，不改 NV，不靠 initramfs 解密。
5. 静态 ARM64 工具在 /dev 内执行，先做当前相同容量的能力检查（不是缩容 dry run），
   再由原厂 Android 内核的 F2FS_IOC_RESIZE_FS 搬移尾部数据。一个脱离 ADB
   会话的加锁 worker 连续完成缩容、备 GPT、主 GPT、flush 与回读。
6. 写入阶段取消会延迟至文件系统/GPT 一致。ADB 断开不自动启动格式化。
   中断后核对原表/候选表；只有已知新文件系统和已知 GPT 副本才能续写。
   未知中间状态停止供恢复，不能猜测成功或直接擦除。
7. 正常重启 Android，确认新 boot ID、映射大小、UUID、双超级块及空闲范围，
   再交给现有空闲区安装流程。E5 创建根分区后还可能再正常重启一次刷新节点。
   原始缩容前 GPT 备份仍保留为卸载归还空间的依据。
8. 内核拒绝在线操作时先证明未改变文件系统/GPT；然后用户可输入 yes
   生成清空数据的新计划，仍需重新勾选确认才可执行。不会自动擦除。

本次接入的是统一 Tauri GUI 的规划和事务流程。原独立 CLI 脚本仍保留原有
离线安装行为，不宣称所有旧 CLI 也已自动改用在线缩容。

## 2026-10-30：缩容后交接旧桌面入口

F50 的用户诊断显示：在线缩容及 Android 重启核验已成功，8 GiB 已回收，
但随后报告 `GPT changed during preflight; nothing was installed`。
原因是 GUI 的旧入口备份代理将缩容前 GPT 当成当前预检快照交给桌面入口，
与它刚读到的缩容后 GPT 不同；不是这份日志中的缩容失败或未知 GPT 损坏。

代理现在仅在在线缩容状态为 verified、恢复文件哈希与原始备份一致、
候选表精确等于该次 userdata 缩容结果时，向旧入口交付缩容后的 GPT 快照，
并为复制出的文件生成对应校验清单。主备份目录中的原始 GPT 和身份记录不覆盖，
继续供恢复与卸载归还空间使用。旧入口针对实际磁盘变化的预检仍保留。

回归涵盖 eMMC/512、UFS/4K、Android A/B、损坏恢复文件、未完成缩容、
不相干分区改动及原始备份不符。MU300 还执行真实桌面 install 入口：
旧快照可复现报错，新快照能通过交接；真正变化的磁盘快照仍在载荷/写入前停止。
这些为离线回归，没有再次缩容用户设备。修复在冻结后端中，旧 EXE/App 需重编。

## 构建与维护

- 核心：installer/backend/online_shrink.py；两仓库相同协议与实现。
- 设备工具：installer/device/f2fs-online.c、build.json 和静态 ARM64 可执行文件。
- 修改 C 后通过固定入口运行 installer/build-online-helper.py，先执行原生 C
  几何/真实临时文件写入回读测试，再交叉编译；没有复制内核或 rootfs。
- 原生安装器构建检查源码/二进制指纹，冻结后端内置工具；不依赖 Android Python。
- 本次变更后旧 EXE/App 指纹会失效，不能改元数据冒充重编，正式包需重新构建安装器。
- 电脑 metadata 备份可能包含加密密钥，只应与私人安装记录一起保管。

- 之前经授权的畅行60：实际保留加密 Android 在线释放64 GiB，正常重启后核验
  双超级块、UUID、包列表、文件和映射容量；见 E5 仓库 docs/CHANGXING60-ONLINE-SHRINK-20261029.zh-CN.md。
- 本次另以新静态工具只读 inspect 核验同机原容量仍保持；没有再次缩容或写 GPT/NV。
- 源码测试覆盖 eMMC/512 与 UFS/4K 的 GPT 精确改动及卸载原始布局恢复；A/B
  新旧续装记录；内核拒绝、ADB 在启动后中断、已知混合 GPT、副本校验、取消延迟、
  Android 在提交期间重启、显式后备确认和新计划二次确认。
- 生产前端浏览器检查中英文、小窗口、默认在线/主动离线、取消/重新打开时清空
  yes、nonce 绑定、新清空计划不得自动开始；保留既有帮助、日志、toast、无线 ADB。
- 这些不等于两仓库每个机型的原厂内核都通过了真实在线缩容。新 detached worker
  的完整整机安装及断电硬件验收尚未执行，不能把模拟测试称为硬件通过。
