# 看板邻区与启动管理入口（2026-11-26）

## 行为

- MU300 / Pro 邻区刷新状态收入标题右侧的固定高度区域，空闲、刷新和失败不增加表格行、不推移表格。E5 原本没有这行刷新提示，不新增无效提示。
- 系统菜单新增「切换到 Android」。独立页面显示永久／临时启动状态、永久启动开关及「关机或重启」「切换到 Android」两个主按钮。
- 独立页面与看板共用 `mu300/boot-controls.js` 中的弹窗和动作。保留各平台原有 Android 提示文字；E5 不套用 MU300 / Pro 的七次回退说明。
- 设为临时启动仅调用既有事务型 next-boot 程序的 `android` 命令，保存下次启动意图；不自动重启。明确确认「切换到 Android」仍沿用已有的写入后延迟重启路径。
- 新增控制使用 ucode，启动标识／misc 写入继续由原有启动程序和共享锁负责。页面按进入、操作完成和窗口重新获得焦点读取实际状态，不增加后台服务或定时轮询。
- 关机、重启及系统切换不依赖数据 SIM 可用性；蜂窝操作的原有 SIM 检查和 AT owner 不变。

## 六轮离线回归

1. 真正的 LuCI 模块加载器加载公共控制模块；共享菜单翻译和新页面依赖有效，避免 `factory yields invalid constructor`。
2. 浏览器执行真实页面和弹窗：取消、Escape、重复点击、页面退出后确认均不误执行；看板与独立页 Android 弹窗内容一致，关机／重启选择不变。
3. 永久→临时→永久的请求及实际状态回读；保存完成前不提前改变开关，未知状态禁用开关，返回页面刷新状态。
4. 后端拒绝、传输失败、重复提交和卸载后的迟到响应；控件恢复，未添加 SIM 或 AT 查询依赖。既有看板快捷控制和刷新调度回归通过。
5. 360 / 1280 像素、中文／英文／土耳其文的真实 DOM 布局；邻区空闲、刷新、错误的表格几何一致。三仓库共 18 组页面场景。
6. 在只读复用的 ARM64 准备根中执行实际 rpcd 入口→action→ucode→原有 next-boot 程序。misc 和状态文件全部重定向到隔离临时文件；分别覆盖 Linux A/B、缺失程序、锁竞争、持久化失败后恢复原 misc／启动设置、错误后的成功重试。不挂载设备分区，不执行真实重启。

测试脚本：`boot_settings_browser.py`、`boot_settings_runtime.py`、`boot_settings_target.sh`；Pro / MU300 位于 `tests/`，E5 位于 `openwrt/tests/`。浏览器脚本可用 `--repo` 检查指定仓库，`--luci` 指向交付根的 luci.js（相邻 cbi.js），以验证真实加载器。

正式包的已有 Makefile 完整复制 `htdocs/`、`root/` 和 LMO，公共模块、页面、菜单及 ucode 位于镜像拥有的可更新路径，不在配置保留目录。没有增加开机动作，也不在更新时修改用户默认启动选择。本轮未打包、未部署；离线回归不代表新增实机开关机验收。

后续启动策略及单次页面状态刷新已按用户新要求调整，见 [临时启动自动永久](BOOT-AUTO-DEFAULT-20261126.zh-CN.md)。上文“没有增加开机动作”描述的是独立入口初次实现。
